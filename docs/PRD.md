# PRD — 구매 요청서 누락 확인 PoC (D사 시연용)

- 근거 문서: `04D_시연평가_교육기획안.docx` (Ablearn 파트너강사 6기 · SCENARIO 04)
- 시연 위치: M03 PoC 설계 · 공통 시연 「후보 A: 구매 요청서 누락 확인」 (15분)
- 문서 상태: v0.1 (2026-09-17)

## 1. 배경

D사(가상)는 여러 현장의 자재 구매를 본사에서 지원한다. 현장지원팀은 불완전한 구매 요청 때문에 추가 문의를 반복하고, 구매팀은 견적의 단위·배송 조건 확인에 시간을 쓴다. 경영진의 AI 과제 발굴 요청에 대해 부서들은 "견적 자동화", "보고서 자동 생성"처럼 기능 이름을 먼저 제안했지만 문제·자료·범위가 구체화되지 않았다.

교육 기획안은 이를 **한 자재군 · 한 업무 단계**로 좁혀 "구매 요청서 1건에서 필수 항목 누락·모호함을 찾고, 보완 질문을 만들고, 사람이 확정하는" 작은 PoC로 검증하자고 제안한다. 이 PRD는 그 PoC를 강의 시연과 조별 실습에서 실제로 돌려 볼 수 있는 형태로 정의한다.

## 2. 목표 / 비목표

### 목표
1. 가상 구매 요청서 1건을 입력하면 **원문 값 / 표준명 후보 / 확인 필요**가 구분된 누락 표시표를 만든다.
2. 누락·모호·불일치 항목마다 **근거(원문 위치)** 와 **보완 질문 초안**을 붙인다.
3. AI 제안과 사람 확정을 **역할표**로 분리해 남긴다.
4. 기획안 §5-3 지표(누락 탐지율·오탐 비율·중요 오류·원문 추적 가능 비율·작업시간)를 **정답표 기반으로 자동 산출**한다.
5. 기획안 §3-2 게이트 위반(원문 없는 값 기입, 모호 표현의 날짜 단정, 별칭 기반 규격 병합)을 **자동 탐지**해 실패 장면 소재로 쓴다.
6. 도구 접속이 안 되는 교실에서도 **오프라인 예시**만으로 같은 활동을 진행할 수 있다.

### 비목표
- 운영 시스템, ERP 연동, 실제 거래 자료 처리
- 견적 자동 발주, 최저가 자동 선정 (후보 B 범위 밖)
- AI 개념·리터러시 설명, 도구 UI 투어
- 후보 B·C·D의 동작 로직 (활동지 양식만 제공)

## 3. 사용자와 사용 상황

| 사용자 | 상황 | 필요 |
|---|---|---|
| 강사 | 15분 공통 시연, 리허설, 지표 예시 산출 | 재현 가능한 시연 사례 1건, 실패 장면 1건, 정답표·지표 리포트, 오프라인 캡처 |
| 학습자(4명×6조) | 8–13분 조별 실습, M03 기획안 작성 | 복붙용 프롬프트, 필수 항목표, 용어 사전, 누락 표시표·역할표 활동지 |
| 내부 과제 검토회의(가상) | PoC 기획안 검토 | 입력 자료·기대 결과·사람 판단·성공/중단 기준이 담긴 기획안 8칸 |

학습자 도구 조건: ChatGPT(또는 동등 생성형 AI) + 스프레드시트. 시나리오에 도구 지정이 없으므로 **가정**으로 표시한다. 본 저장소의 Python 스크립트는 강사 검증용이며 학습자에게 요구하지 않는다(가정).

## 5. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 자재군 1개(교육용 가상 "배관 자재군")의 필수 항목표를 제공한다: 공통 5항목(품목 ID·수량·단위·희망일·배송 위치) + 자재군 추가 1항목(규격) | 필수 |
| FR-02 | 용어 사전: 품목 ID ↔ 표준명 ↔ 별칭 ↔ 표준 단위. "비슷하지만 다른 규격" 함정을 최소 2쌍 포함 | 필수 |
| FR-03 | 가상 구매 요청서 30건, 5유형(정상/필수 누락/모호 표현/단위 불일치/배송조건 누락) 균등. 각 건에 읽기 쉬운 버전과 저품질 스캔 버전 | 필수 |
| FR-04 | 정답표: 건별·항목별 상태(충족/누락/모호/불일치)와 원문 위치 | 필수 |
| FR-05 | 추출: 요청서 텍스트 → 항목별 `원문값·원문위치·표준명후보·근거` JSON. 값이 없으면 `null`. 규칙 기반 백엔드(오프라인)와 생성형 AI 백엔드(API 키 있을 때, 가정)를 같은 스키마로 제공 | 필수 |
| FR-06 | 규칙 검사(AI 아님): 필수 항목표 대조 → 상태 판정 + 근거 문장 | 필수 |
| FR-07 | 보완 질문 초안: 확인 필요 항목만 대상으로 현장 담당자에게 보낼 질문 생성 | 필수 |
| FR-08 | 게이트 검사기: (a) 원문 위치 없는 값 (b) 원문에 존재하지 않는 값 (c) 모호 표현을 날짜로 단정 (d) 사전에 없는 별칭→표준명 병합 (e) 규격 미기재를 채움 | 필수 |
| FR-09 | 지표 평가: 정답표 대조로 탐지율·오탐 비율·중요 오류 건수·원문 추적 비율 산출, 유형별 분리, Markdown 리포트 | 필수 |
| FR-10 | ChatGPT 붙여넣기 출력(JSON)을 그대로 받아 FR-06~FR-09를 수행 | 필수 |
| FR-11 | 스프레드시트 활동지(xlsx): 누락 표시표, 역할표, PoC 기획안 필수 8칸, 5항목 평가표(0–2점) | 필수 |
| FR-12 | 프롬프트 팩: 시스템 규칙 / 추출 / 규칙 검사 보조 / 보완 질문 — 학습자 복붙용 | 필수 |
| FR-13 | 실패 장면 잘못된 초안 1건 + 게이트 검사기 지적 결과 | 필수 |
| FR-14 | 오프라인 캡처: 시연 사례와 조별 표본 6건의 추출 결과·규칙 검사 결과 Markdown | 필수 |
| FR-15 | 15분 시연 스크립트(강사 발화·클릭 순서·확인 질문) | 필수 |
| FR-16 | 시간 기록지 양식(수동 vs AI 보조, 검토·수정 시간 포함) | 권장 |

## 6. 게이트(비기능 요구사항)

기획안 §3-2를 코드로 강제한다.

- G1 값이 없으면 비우거나 `확인 필요`로 둔다. 원문 없는 값을 채우지 않는다.
- G2 "다음 주", "빨리", "이번 달 안" 같은 모호 표현을 날짜로 단정하지 않는다.
- G3 별칭이 비슷하다는 이유만으로 다른 규격을 합치지 않는다.
- G4 모든 추출 값은 원문 위치로 추적 가능해야 한다(100%).
- G5 최종 확정 칸은 항상 사람 몫으로 남긴다. AI 출력은 "제안" 열에만 들어간다.

## 7. 성공 지표 (교육용 목표, 기획안 §5-3)

| 지표 | 정의 | 목표 |
|---|---|---|
| 누락 탐지율 | 찾은 확인필요 항목 ÷ 정답표 확인필요 항목 | ≥ 95% |
| 잘못된 누락 경고 비율 | 정답이 충족인데 경고한 항목 ÷ 전체 경고 | ≤ 10% |
| 중요 오류 | 품목·수량·단위·희망일이 정답에서 확인필요인데 충족으로 표시 | 0건 (소표본 ≠ 운영 무오류) |
| 원문 추적 가능 비율 | 원문 위치가 있고 그 위치 텍스트가 값과 일치하는 추출 값 ÷ 전체 추출 값 | 100% |
| 건당 실제 작업시간 | 열기·입력·검토·수정 포함 | 중앙값 30% 단축 (시간 기록지로 측정, 본 PoC는 양식만 제공) |

수치 목표는 교육용 가정이며 기준선 측정 후 조정한다.

## 9. 가정과 한계

- 자재군·품목 ID·규격·별칭은 모두 교육용 가상이며 실제 건설 자재 규격을 뜻하지 않는다.
- 생성형 AI 백엔드는 API 키가 있을 때만 동작하며, 기본 시연은 ChatGPT 웹 + 붙여넣기 JSON을 전제로 한다.
- 규칙 기반 추출기는 오프라인 대체 수단이자 규칙·게이트·평가 코드의 테스트 기준이다. 실제 AI 성능을 대표하지 않는다.
- 표본 30건은 교육용 소표본이며 운영 성능을 보증하지 않는다.

## 10. 리스크

| 리스크 | 대응 |
|---|---|
| AI가 "다음 주"를 날짜로 채움 | 프롬프트 금지 지시 + 게이트 검사기 G2가 잡아 실패 장면으로 전환 |
| 저품질 스캔에서 추출 편차 | 유형별 지표 분리 보고, 판독 불가는 `모호(판독)`로 사람 판단 |
| 교실 인터넷 불가 | 오프라인 캡처만으로 8–13분 실습 진행 |
| 학습자가 빈칸을 임의로 채움 | 활동지 `사람 확정` 열과 `근거` 열을 필수로 두고 순회 확인 |
