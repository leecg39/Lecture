# poc-d04 — 구매 요청서 누락 확인 PoC (D사 시연용)

Ablearn 파트너강사 6기 시연평가 · SCENARIO 04(건설·시설관리) · `04D_시연평가_교육기획안.docx`의
M03 공통 시연 「후보 A: 구매 요청서 누락 확인」을 실제로 돌려 볼 수 있게 만든 교육용 PoC입니다.

> 모든 품목 ID·규격·현장명·요청서는 교육용 가상이며 실제 건설 자재 규격이나 거래 자료를 뜻하지 않습니다.
> 표본 수와 지표 목표는 교육용 가정입니다.

## 무엇을 하는가

```
요청서 1건 ─ 추출(AI 또는 규칙) ─ 규칙 판정 ─ 게이트 감사 ─ 보완 질문 ─ 누락 표시표 · 역할표
                                                     └─ 정답표 대조 → 탐지율·오탐·중요오류·추적율
```

- **AI 축**(제안): 원문 값·표준명 후보·보완 질문 초안. ChatGPT 웹(학습자) 또는 규칙 추출기(오프라인).
- **규칙 축**(결정적): 필수 항목표 대조 → 충족/누락/모호/불일치. 게이트 G1–G5 위반 탐지. 정답표 대조 지표.
- **사람 축**: 활동지의 '사람 확정' 열. 코드가 절대 채우지 않는다.

## 빠른 시작

```bash
make setup        # .venv + openpyxl, pytest
make all          # data/ 생성 → 규칙 백엔드 실행 → out/ 리포트·xlsx → examples/
make test         # 테스트(pytest)
```

`python -m poc_d04 --help`로 개별 명령(`gen`, `run`, `check-paste`, `eval`, `workbook`, `examples`)을 볼 수 있습니다.

## 학습자 도구 조건

시나리오에 도구 지정이 없어 **ChatGPT(또는 동등) + 스프레드시트**를 가정합니다. 이 저장소의 Python은 강사 검증용(정답표·지표·게이트 감사)이며 학습자에게 요구하지 않습니다. `--backend llm`은 `OPENAI_API_KEY`가 있을 때만 동작하는 선택 경로(가정)입니다.

## 게이트 (기획안 §3-2)

| 코드 | 규칙 |
|---|---|
| G1 | 값이 없으면 비우거나 '확인 필요'. 원문 없는 값을 채우지 않는다. |
| G2 | '다음 주' 같은 모호 표현을 날짜로 단정하지 않는다. |
| G3 | 별칭이 비슷하다는 이유만으로 다른 규격을 합치지 않는다. |
| G4 | 원문에 없는 규격을 채우지 않는다. |
| G5 | 최종 확정은 사람이 한다. |

## 한계

- 규칙 추출기는 오프라인 대체 수단이자 규칙·게이트·평가 코드의 테스트 기준입니다. 실제 생성형 AI의 성능을 대표하지 않습니다.
- 30건 소표본의 "중요 오류 0건"은 운영 무오류를 뜻하지 않습니다.
- 요청서 1건 = 품목 1개를 전제합니다. 품목이 둘 이상이면 "복수 품목 의심" 경고만 내고 첫 품목만 처리합니다.
- 현장명은 `A현장`처럼 영대문자 1글자 + 현장 형식만 인식합니다(교육용 가정).
- 실제 교실 리허설은 기획안 작성 시점에 수행하지 않았습니다(기획안 §8).
