# 15분 시연 스크립트 — 구매 요청서 누락 확인

화면: `npm run dev` 후 키보드 1–5.

## 0–2 · 도입 (키 1)

성공은 “문서 생성”이 아니라 **추가 문의 항목을 찾았는가**. 산출물은 누락 표시표.

## 2–6 · 시연 (키 2)

원문: `A현장, 품목 P-01 20개, 다음 주 필요.`

확인할 것:

- 원문 값: P-01, 20, 개
- 확인 필요: 희망일(다음 주), 배송 위치(A현장)
- `다음 주`가 날짜로 바뀌지 않음
- 규격 50A는 원문 값이 아님(규칙 열의 사전 적용)

## 6–8 · 실패 장면 (키 3)

잘못된 초안이 날짜·창고·규격을 채움. 게이트 G2·G1·G4·G5. 학습자는 위험 한 줄.

## 8–13 · 실습 (키 4)

표본 1건. 원문 값 / 확인 필요 / 사람 확정 칸. 빈칸을 임의로 채우지 않음.

## 13–15 · 성공 기준 (키 5)

탐지율 95% 등은 **교육용 가정**. 원문 추적과 확인 필요 건수만 이 화면에서 본다.
